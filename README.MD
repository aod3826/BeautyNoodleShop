#นี่คือสรุปภาพรวมการทำงานของระบบในปัจจุบัน 
1. เส้นทางการสั่งซื้อของลูกค้า (Customer Journey - Frontend)
การเข้าถึง: ลูกค้าเข้าผ่าน GitHub Pages ซึ่งทำหน้าที่เป็น UI (หน้ากาก) ของระบบ

การดึงข้อมูล: ระบบจะเรียก API จาก GAS เพื่อเช็กว่า "ร้านเปิดหรือไม่" และดึงรายการเมนูมาแสดงแบบ Real-time

การเลือกอาหาร: มีระบบ Logic ที่ฉลาด (Step-by-Step) ลูกค้าต้องเลือกตามลำดับ (เส้น > น้ำ > เนื้อ) และสามารถระบุตัวเลือกเสริม (พิเศษ/ไม่ผัก) ได้ตามที่ตั้งค่าไว้ใน Google Sheets

การส่งออเดอร์: เมื่อลูกค้ายืนยัน ระบบจะส่งข้อมูลแบบ JSON ไปยัง Backend โดยตรง ไม่ผ่านหน้าจอแชท ทำให้ข้อมูลแม่นยำ

2. การทำงานของสมองส่วนกลาง (Backend - GAS)
Data Integrity: เมื่อได้รับออเดอร์ Backend จะไม่เชื่อราคาจากหน้าบ้าน 100% แต่จะทำการ "คำนวณราคาใหม่" จากฐานข้อมูลใน Sheets เพื่อป้องกันการแก้ไขราคา

Database: บันทึกข้อมูลลงใน Google Sheets แยกตามชีต Orders (เก็บออเดอร์) และ Logs (เก็บประวัติการทำงาน)

Automation: หลังจากบันทึกลง Sheet สำเร็จ ระบบจะทำหน้าที่เป็น "พนักงานส่งข่าว" เรียกฟังก์ชันส่ง LINE Flex Message ทันที

3. มุมมองของแม่ค้า (Merchant Journey - Phase 3)
นี่คือส่วนที่เพิ่มเข้ามาใหม่และเปลี่ยนจากแอปฯ ธรรมดาให้กลายเป็นระบบจัดการร้านครับ:

Real-time Notification: เมื่อมีออเดอร์ใหม่ แม่ค้าจะได้รับ Flex Message ในกลุ่ม LINE ที่มีดีไซน์สวยงาม อ่านง่าย (แยกรายการอาหารและตัวเลือกชัดเจน)

Interactive Buttons: แม่ค้าไม่ต้องพิมพ์ตอบ แต่ใช้การ "กดปุ่ม" บนข้อความนั้นเลย:

[✅ รับออเดอร์]: เมื่อกดแล้ว ระบบจะไปแก้สถานะใน Google Sheets เป็น 'Processing' และส่งข้อความตอบกลับในกลุ่มว่า "รับออเดอร์แล้วโดย [ชื่อแม่ค้า]" เพื่อป้องกันการทำซ้ำ

[🏁 เสร็จแล้ว]: เปลี่ยนสถานะเป็น 'Completed' เพื่อปิดงาน

[📞 โทรหาลูกค้า]: กดแล้วโทรออกได้ทันทีจากหน้าจอ LINE

Webhook: ระบบมี Webhook ที่คอยฟังคำสั่งจากปุ่มเหล่านี้ตลอด 24 ชม.

📊 สรุปโครงสร้างปัจจุบัน
Frontend: GitHub Pages (HTML/Tailwind/JS)

Backend/API: Google Apps Script (JSON API)

Database: Google Sheets

Notification/Control: LINE Messaging API (Flex Message + Webhook)
